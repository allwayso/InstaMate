### ★ F3/F4 标定（第 2 条的核心，也是我最需要你做的）

轴向映射是**推导不来**的 —— Kalidokit 的 `rigArm()` 里混了左右反向、非线性耦合项和 clamp。
所以计划里把它做成一轮显式标定。你需要做的就是**抬几次手**，然后告诉我结果：

**F3（左右）**：抬**右手**，看输出里哪个键在变。

```js
// 浏览器控制台（页面已导出）
__mocapDebug.getState()          // 当前状态机状态
__mocapDebug.isMeasured()        // false = 还没标定
```

- 若变的是 `LeftUpperArm` → 把 `retarget-profile.ts` 的 `swapLeftRight` 改成 `true`
- 若变的是 `RightUpperArm` → 保持 `false`
- 页面上也有「左右交换（标定用）」开关，可以实时对比，**不用改代码**

**F4（轴与符号）**：分别做三个动作，记录哪个分量在变、方向如何

| 动作 | 期望落到 | 要确认的 |
|---|---|---|
| 抬右臂 | `rightUpperArm` 绕 **Z** 负方向 | `UpperArm.z` 是不是主导项 |
| 屈右肘 | `rightLowerArm` 绕 **Z** 负方向 | `LowerArm.z` 的符号 |
| 头向自身左转 | `head` 绕 **Y** 正方向 | `Face.head` 哪个分量在变 |

标定完成后：
1. 把实测结果写进 `web/lib/mocap/retarget-profile.ts` 的 `RETARGET_RULES`
2. 把 `RETARGET_IS_MEASURED` 改成 `true`（页面警告条消失）
3. 在文件头补上「实测于 …，判据 …」
4. 重跑 `npm test`（测试只锁机制不锁轴向，所以不会因为改常量而失败）

## 四、阶段内实测得出的关键事实（都写进代码注释了）

| # | 事实 | 怎么得出的 |
|---|---|---|
| F1 | Kalidokit 签名 `Pose.solve(lm3d, lm2d, opts)` 与计划一致 | 读 `dist/PoseSolver/index.d.ts` |
| F2 | **`lm3d` 必须是 `poseWorldLandmarks`（米）**，喂归一化点会让整条手臂被丢弃 | 源码离屏守卫 `lm3d[15].y > 0.1` 是米语义；实测归一化 → 恒为 −1.25（RestingDefault），米制 → 随姿态变 |
| F3 | Kalidokit 的 `Right*` 读的是 MediaPipe 的 `left_*` 点 | `calcArms` 用 `lm[11],lm[13]` 算 `r`；守卫用 `lm[15]` 当 rightHand |
| F4 | 输出是 Kalidokit 自己的 rig 空间，不可推导 | `rigArm()` 里有 `invert=±1`、非线性耦合、clamp |
| F5 | `kalidokit` 的 main 是 ESM + 无扩展名目录导入，**Node 加载不了** | Node 报 `Directory import is not supported`；但 Turbopack 能解析，**不需要 transpilePackages** |
| F6 | MediaPipe 需要 10 个文件，**simd 与非 simd 分支不对称** | `grep` 出 direct requests；非 simd 分支没有 `.data` |
| F7 | `compat.vrm` 正好压到两个能力分支且**骨长不同** | 用仓库自带 `inspect-vrm.mjs` 实测（见下） |
| F8 | `gen-clips` 整体重写 index 会**抹掉录入的动作** | 实测复现：塞一条 mocap 条目 → 跑生成器 → 目录从 7 条变回 6 条 |
| F9 | 10 秒录制的原始关键点可能 5–10 MB | 按点位与帧数估算；故 `data/mocap/` 不进 git |
| F10 | `Euler('XYZ') === Rx×Ry×Rz` | three.js 0.186.0 实测（与 `Rz×Ry×Rx` 差 44.9°） |

### F7 的实测对比（这就是选它的理由）

| | Seed-san（主） | compat.vrm（第二） |
|---|---|---|
| humanoid 骨骼 | 51/55（缺 upperChest, jaw, leftEye, rightEye） | **54/55（只缺 jaw）** |
| 有 upperChest | ✗ | **✓** |

## 五、阶段内发现并修掉的真 bug

| # | 问题 | 症状 | 修法 |
|---|---|---|---|
| 1 | **平滑器只平滑了 4 根骨骼** | `PoseSmoother` 按 `Object.keys(basePose)` 决定平滑哪些骨骼，而 `BASE_STANDING_POSE` 只有 4 根、重定向产出 10 根 → **spine/chest/neck/head 与两只手被静默丢弃**：角色能抬胳膊但脊柱与头完全不动，且不报错 | 改成「基础姿态的键 ∪ 至今见过的 canonical 键」，并加断言 |
| 2 | **`gen-clips` 抹掉录入的动作**（F8） | 录完动作再跑生成器，动作从目录里消失 | 改成读-改-写，抽出纯函数 + 9 项单测 |
| 3 | `npm test` 的目录参数在 Node 24 无效 | `--test ../tests/` 被当成模块路径（`Cannot find module`） | 改 glob `--test "../tests/*.test.mjs"` |
| 4 | API 集成测试 14 项**全被静默跳过** | `test(name, { skip: !available })` 里的 `available` 在**模块加载时**求值，而它是 `before` 钩子才赋值的 → `ℹ pass 0 / skipped 14`，看着"全绿"其实一个没跑 | 把判断放进测试体内 |

### 过程教训

- **删除型操作必须先看退出码再信结果**：修 F8 时我两次得到"探针保留 ✅"的**假阳性** ——
  因为生成器在写入之前就崩了，"没被抹掉"只是因为根本没跑成功。
- **测试注册是即时的**：#4 就是这么踩的，而且它伪装成"全绿"。
