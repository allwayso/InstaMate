# 动作库接入说明 · clip v1

> 面向：B / C / D，以及后续接真人动捕的人。
> 一句话：**只要产出符合本格式的 JSON，就自动进入同一个动作库、使用同一个播放器。**
> 格式常量与校验规则的唯一实现在 `web/lib/clip-spec.ts`（浏览器与 CLI 共用）。

---

## 一、链路

```
程序化动作生成 ───────────────┐
                              ├→ ClipFile v1 → 校验 → 采样/混合 → normalized 骨骼 → VRM 更新 → 渲染
未来：录像 → 动捕 → 重定向 ──┘
```

程序化生成器（`tools/gen-clips.mjs`）**直接产出可保存的标准 JSON 文件**，G1 自带的动作也从文件加载，
所以"未来动作库的实际使用路径"现在就已经在跑了。

---

## 二、文件格式

```jsonc
{
  "schemaVersion": 1,
  "rigProfile": "vrm-normalized-v1",
  "name": "wave-right-hand",        // 动作 id，非空字符串；与目录里的 id 一致
  "space": "normalized-local",
  "rotationMode": "absolute",
  "quaternionOrder": "xyzw",        // [x, y, z, w]
  "fps": 30,
  "frameCount": 121,
  "duration": 4,                    // 必须严格等于 (frameCount - 1) / fps，容差 1e-6
  "loop": false,
  "rootMotion": "locked",           // v1 禁止根位移
  "mask": ["rightLowerArm", "rightUpperArm"],   // 必须与 bones 的键集合完全一致
  "bones": {
    "rightUpperArm": [[0,0,0,1], /* ... 共 frameCount 个四元数 */]
  }
}
```

### 硬性约定（校验器会拦）

| 项 | 约定 |
|---|---|
| 骨骼名 | 必须是 **VRM 1.0 标准人形骨骼名**（55 根，表在 `web/lib/human-bones-vrm1.json`），不是 VRoid 的节点名 |
| 旋转含义 | normalized 骨骼的**绝对局部四元数**（不是相对参考姿态的增量） |
| 时间轴 | 第 n 帧为 `n / fps`；`duration = (frameCount - 1) / fps` |
| 轨道长度 | 每条轨道都必须恰好 `frameCount` 个四元数 |
| 四元数 | 四个有限数字、近似单位长度（偏差 ≤ 1e-3 可通过，> 1e-3 拒绝） |
| 禁令 | 不写根位移、骨骼缩放、表情轨道、弹簧骨轨道 |
| 符号 | 相邻帧点积应为正；负号也能用（采样走最短路径 slerp），但会有 WARN |

> **参考姿态不是基础站姿。** normalized 骨骼全为单位四元数 = **T-pose**（参考姿态，用于坐标校准）。
> 日常待机是「基础站姿」（双臂自然下垂），在 `web/lib/pose.ts` 的 `BASE_STANDING_POSE` 里显式定义。
> 不要把 T-pose 当默认待机姿态。

## 三、怎么加一个动作

### 方式 A：程序化生成（推荐用于测试动作）

在 `tools/gen-clips.mjs` 的 `CLIPS` 里加一条，用关键姿态描述：

```js
{
  id: 'nod',
  displayName: '点头',
  note: '低头 → 回正，重复两次',
  durationSec: 2,
  keys: [
    { t: 0.0, pose: {} },                              // {} = 基础站姿
    { t: 0.6, pose: { head: rotQ('X', 15) } },         // 低头（X 轴为正）
    { t: 1.0, pose: {} },
    { t: 1.4, pose: { head: rotQ('X', 15) } },
    { t: 2.0, pose: {} },
  ],
}
```

```bash
cd web && npm run gen:clips
```

生成器会：按秒插值（缓动 + 最短路径 slerp）烘焙成固定 30 fps → **立即用同一个校验器自检** → 不合格就不写盘。

### 轴向约定（实测得出，不是猜的）

在 normalized 参考姿态（≈ T-pose）的局部系里：

| 轴 | 语义 | 典型用途 |
|---|---|---|
| **X** | 沿骨骼长轴（手臂为自转）/ 俯仰 | 手臂自转、低头抬头 |
| **Y** | 偏航（上下轴） | 转头、手臂在水平面内划动 |
| **Z** | 侧摆（额状面内） | **抬臂/垂臂、屈肘** |

| 动作 | 骨骼 | 轴 | 符号 |
|---|---|---|---|
| 抬右臂 / 抬左臂 | `*UpperArm` | Z | **− / +** |
| 右肘屈 / 左肘屈 | `*LowerArm` | Z | **− / +** |
| 头向角色自身左 / 右 | `head` | Y | **+ / −** |

⚠️ **角色自身右侧 = 世界 −X**（角色面向 +Z，相机在 +Z 侧，所以它的右手在我们视角的左边）。
最易犯的错就是这里看反了 —— 一律用 `rightHand.x < 0` 这类**数值断言**验证，不要靠肉眼看。

### 方式 B：从外部文件导入（真人动捕开始用这个）

调试页有「导入 JSON」按钮：选一个符合格式的文件 → 校验通过后注册为**临时动作**（仅当前会话有效）。

- 重名（与内置动作 id 相同）会被**拒绝**，不静默覆盖内置动作。
- 校验不过会显示具体错误，并**保留原动作/姿态**，不做部分应用。

### 方式 C：进内置目录（动捕动作正式入库）

把 JSON 放进 `web/public/clips/`，并在 `web/public/clips/index.json` 的 `clips` 数组里加一条：

```jsonc
{
  "id": "wave-mocap-01",
  "name": "挥手（动捕）",
  "url": "/clips/wave-mocap-01.json",
  "source": "mocap",          // generated | mocap | imported
  "note": "2026-09-23 用 Insta360 拍摄，MediaPipe+Kalidokit 重定向",
  "fps": 30, "duration": 3.2, "frameCount": 97,
  "mask": ["rightUpperArm", "rightLowerArm"]
}
```

播放器与 UI 无需改动。

## 四、真人动捕接入流程（固定下来）

```
录像 → MediaPipe/Kalidokit → 坐标与参考姿态重定向 → clip v1 导出 → 共用校验 → 同一播放器
```

约束：

- **不把源关键点、Euler 角或人物骨长交给播放器解释。** 播放器只认 normalized 骨骼的绝对局部四元数。
- 重定向要完成：源骨骼名映射、坐标基变换、参考姿态偏移、父子空间转换。
- 保留目标 VRM 的骨长，不做骨骼缩放、不写根位移。
- 导出后先跑 `node tools/validate-clip.mjs <file> --target assets/vrm/<角色>.manifest.json`
  —— 目标资产缺骨骼时会**拒绝**并报出缺失骨骼名。

## 五、校验与检查命令

| 命令（在 `web/` 下） | 作用 |
|---|---|
| `npm run gen:clips` | 重新生成全部程序化动作（可复现） |
| `npm run validate:all` | 校验 `public/clips/` 下全部动作 |
| `npm run validate:clips <file>` | 校验单个文件；`--target <manifest>` 追加目标骨骼检查 |
| `npm run validate:fixtures` | 跑 6 坏 + 1 好夹具，确认规则本身没被改坏 |
| `npm run test:clip` | 15 项播放与插值逻辑测试 |

退出码：`0` 通过 / `1` 存在 ERROR / `2` 文件不可解析（便于接 CI）。

## 六、播放器的对外接口

`web/lib/clip-player.ts` 的 `ClipPlayer`（**不持有 VRM**）：

```ts
play(clip, { fadeIn?, fadeOut?, loop?, startTime? }): Promise<void>
pause() / resume() / stop() / seek(seconds) / reset()
getSnapshot(): { name, state, time, duration, loop, weight, outgoing }
update(delta): Pose          // 每帧调用，返回要写入的骨骼姿态
getBoneNames(): string[]     // 当前参与合成的骨骼（新旧 mask 并集）
```

语义要点：

- 按**秒**采样，与显示刷新率无关；全部走最短路径 slerp。
- 淡入/淡出默认各 0.2 秒；非循环动作到末帧后淡出，淡出结束才 resolve。
- 被新动作取代或 `stop()` 打断 → 以 `ClipPlaybackCancelledError` reject（可识别）。
- 切换时冻结上一个动作的姿态，在**新旧 mask 的并集**上过渡 —— 退出 mask 的骨骼平滑回基础站姿。
- 页面隐藏时挂起时钟，恢复后不跳到结尾。
- `reset()` 是硬清空（无过渡），用于「恢复基础站姿」「参考姿态」和切角色。

`web/lib/character-runtime.ts` 的 `CharacterRuntime` 是**唯一**写入身体骨骼的地方：

- 只写 normalized 骨骼（raw 由 three-vrm 的 `autoUpdateHumanBones` 同步；手写 raw 会造成双写，§七 禁止）。
- 写之前做能力检查：**只要有一根骨骼缺失就整体不写**，返回缺失名单。
- `commit(delta)` 是全流程唯一调用 `vrm.update` 的地方；每帧调用次数可被测试断言。

未来 `CharacterController.playClip(name)` 只需：目录里解析出 URL → 加载校验 → 委托 `ClipPlayer.play()`。
