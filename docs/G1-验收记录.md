### ⚠️ 判读时必须知道的一件事

Seed-san 自带一个名为 **`robo_arm`** 的道具网格（独立根节点，**不挂在人形骨架下**）。
它在 T-pose、基础站姿、所有动作里**都不动** —— 这不是"网格没跟着骨骼动"，是资产设计如此。
验收骨骼变形时应忽略它。已写入 `assets/vrm/sample.manifest.json` 的 `knownIssues`。

## 五、本轮改掉的两个自己踩的坑

**1. 屈肘一开始做在错误的轴上（看渲染才发现）**
初版把屈肘放在 Y 轴 → 前臂朝相机方向压过去，正面**透视缩短、几乎看不出来**。
在参考（T-pose）局部系里，肘的屈曲轴其实是 **Z**（前臂在额状面内抬起）。
自动化断言当时是"手向前移动（+Z）"并通过了 —— **断言写对了轴，但轴本身选错了**，
是截图暴露的。教训：坐标断言能保证"确实绕了某轴"，**保证不了"这个轴是对的"**，两者都要看。

**2. `恢复基础站姿`/`参考姿态` 按钮用 `stop()` 失效**
`stop()` 会进入 fadeOut，渲染循环每帧仍把旧动作的骨骼写回去，把手动设置的姿态覆盖。
改用 `player.reset()`（current 与 outgoing 全清）。这也是"每帧只有一个写入者"这条约束的必然结果。

## 六、已知取舍

| 项 | 现状 | 说明 |
|---|---|---|
| 两处 slerp 实现 | `clip-spec.ts` 与 `pose.ts` 各有一份 | 因为两个文件都要能被 Node 直接加载而必须自包含。已用 200 组随机比对测试锁住一致性；若改动插值必须两处同改 |
| 动作未做骨骼缩放限制的运行时校验 | 由格式结构性保证（轨道只能是四元数） | 无需运行时拦截 |
| 未接入注视/呼吸/嘴型/状态机 | 按计划不做 | 归 G3/G4 |
| 导入动作仅会话内有效 | 刷新即失效 | 按计划如此；持久化需要目录写入，属后续 |
| G1 只用 Seed-san | 未在第二个角色上验证 | **正是 G2 的验收内容**，本轮不覆盖 |
